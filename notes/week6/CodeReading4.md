# CodeReading4 代码阅读问答
## 问题1：Agent.java:184 的try-catch为什么要包裹整段think()？如果不catch会怎样？
### 1. 包裹think()方法的原因
1. **保护Agent核心生命周期**：think()是Agent的核心业务逻辑，内部会抛出各类运行时异常（计算、通信、状态处理异常）。若think()抛出异常未捕获，会直接中断当前Agent执行流程，导致Agent停止工作。
2. **异常隔离**：单个Agent的业务错误不能终止整个程序/其他Agent，catch捕获后打印堆栈，Agent可以继续下一轮think循环，保证程序整体可用。
3. **统一异常兜底**：think()内部包含多段子逻辑，每段单独try-catch冗余，外层统一捕获简化代码，统一做异常日志/堆栈输出。

### 2. 如果不catch的后果
1. 受检/非受检异常会向上抛出到上层调用栈，若无上层throws声明，直接触发程序崩溃；
2. Agent线程终止，该Agent彻底停止运行，无法继续执行任务；
3. 异常堆栈丢失（若无全局异常处理器），无法定位故障代码；
4. 若多Agent共用主线程，单个Agent异常会导致全部业务瘫痪。

## 问题2：项目中为什么各处都打日志？日志4个级别分别对应什么场景？
### 1. 项目大量打印日志的作用
1. **线上故障排查**：无调试器时，日志记录程序执行轨迹、入参、异常堆栈，快速定位BUG；
2. **运行状态监控**：记录启动、配置加载、线程执行、消息收发等关键节点，判断程序是否正常运行；
3. **行为追溯审计**：记录Agent交互、配置修改、任务执行记录，用于事后复盘；
4. **性能分析**：通过日志时间戳统计步骤耗时，定位性能瓶颈；
5. **区分运行信息与报错**：分级日志过滤无关输出，生产环境只保留关键日志，减少IO开销。

### 2. 日志4个基础级别（DEBUG/INFO/WARN/ERROR）对应场景
1. **DEBUG（调试级）**：开发调试用，打印详细中间数据、变量值、流程分支。例：SampleFireBrigade.java打印接收的消息内容。生产环境默认关闭。
2. **INFO（信息级）**：正常业务关键节点，记录程序正常执行流程。例：读取配置文件成功、Agent启动、线程创建、配置解析完成。
3. **WARN（警告级）**：程序未崩溃，但存在非预期、可恢复的异常情况。例：配置行格式错误、连接超时自动重试、参数存在默认兜底。
4. **ERROR（错误级）**：功能执行失败，当前操作无法完成，但程序整体可继续运行。例：文件不存在、IO读取失败、接口调用报错。
   补充：FATAL（致命级，拓展）：严重错误，程序必须终止，如核心配置缺失、内存溢出。
